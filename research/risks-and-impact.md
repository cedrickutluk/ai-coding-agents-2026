# AI Coding Agents: Risks, Limitations, and Impact on Developers

## Overview
This document outlines the security risks, reliability limitations, and long-term impact on developers associated with integrating AI coding agents into modern software engineering workflows.

Researcher: Sebastian Gonzalez

---

## 1. Reliability & Security Risks
- **Elevated Vulnerability Rate in GenAI Output:** Empirical studies from Synk and Veracode indicate that AI code generators output security vulnerabilities in 35% to 45% of generations. Common Flaws include OWASP Top 10 risks such as SQL Injection (CWE-89), Cross-Site Scripting (CWE-79), and improper input validation.
- **Package Hallucination & Supply Chain Attacks ("Slop Squatting"):** AI models frequently invent non-existent package dependencies or library names (package hallucination). Attackers exploit this behavior by registering these hallucinated package names on public registries like npm or PyPI with embedded malware, tricking developers who install AI-suggested dependencies.
- **Codebase Degradation and "Slop Code":** The rapid generation of unverified code leads to an accumulation of low-quality, redundant, and non-optimized snippets ("slop code"). Over time, this creates severe architectural debt and structural brittleness within enterprise codebases.
- **Secret & Telemetry Exposure:** Uploading proprietary source code, internal API endpoints, or environment tokens to cloud-hosted AI coding assistants risks intellectual property exposure and accidental data leaks if prompts are used for model training. 

## 2. Why Human Review and Testing Remain Essential

- **Lack of Contextual Understanding:** AI agents evaluate code line-by-line or within prompt windows, but lack deep understanding of business logic, domain constraints, and system architecture.
- **Verification vs. Generation:** While AI can rapidly generate hundreds of lines of code, verifying correctness requires comprehensive automated testing (unit, integration, regression) and expert code review.
- **Accountability & Liability:** AI models cannot take responsibility for system failures, compliance breaches, or outage costs. The software engineer remains strictly accountable for code deployed to production.
- **Contextual Blind Spots:** LLMs generate code sequentially based on local context windows or prompt boundaries. They lack global architectural awareness, failing to enforce project-specific business logic, authorization rules, or existing design patterns.
- **Verification Bottleneck:** According to the *Sonar State of Code Developer Survey*, 96% of developers do not fully trust AI-generated code to be functionally correct, and 95% spend significant time reviewing and debugging AI output. While generation is fast, validation remains a human intensive bottleneck.
- **Erosion of Automated Verification:** Research indicates that while AI tool usage has surged, only 48% of developers consistently run automated security scans before merging AI-assisted pull requests, creating a gap where subtle vulnerabilities pass undetected into production.
- **Legal & Compliance Accountability:** AI models cannot be held legally or financially liable for system outages, data breaches, or compliance failures. The human developer remains solely responsible for code deployed to production.

---

## 3. Shifting Responsibilities for Developers

- **From Code Writers to Code Auditors:** Developers spend less time writing repetitive boilerplate syntax and significantly more time reading, auditing, and refactoring AI-generated code. Code review and validation have become the primary skills in AI-assisted workflows.
- **Emphasis on System Architecture & Security:** Focus shifts toward high-level system design, threat modeling, API integration, and prompt engineering/orchestration.
- **Quality Assurance Emphasis:** Developers must develop stronger skill sets in unit testing, debugging, and edge-case scenario evaluation.
